# 02 — MCP сървър от нулата

**Цел.** Да напишете, на ръка, без SDK и без framework, сървър, който говори MCP
(Model Context Protocol) — протоколът, чрез който агент открива и извиква инструменти.
Тук няма модел и няма мрежа: MCP е JSON-RPC 2.0 съобщения по стандартен вход/изход
(stdin/stdout). Целта е механиката на протокола да ви е ясна, преди в лекция 4 да минете
към готови агентни framework-и (VoltAgent, LangGraph.js), които я скриват.

**Очакван резултат.** `npm test` минава — вашият сървър отговаря правилно на
`tools/list` и `tools/call`, и не пада при непознат инструмент.

---

## Какво е MCP тук, накратко

Клиент (агент) стартира вашия сървър като процес и си говорят по JSON-RPC 2.0, по един ред
JSON на съобщение:

1. `initialize` — ръкостискане: коя версия на протокола, кой е сървърът.
2. `tools/list` — сървърът обявява кои инструменти има и каква е тяхната JSON Schema.
3. `tools/call` — клиентът извиква инструмент по име, с аргументи; сървърът връща резултат.

Важно правило: **stdout носи само JSON-RPC съобщения.** Ако някъде напишете
`console.log` за дебъг, ще счупите протокола за всичко след него. За дебъг ползвайте
`console.error` (stderr).

## Инструментът за това упражнение: `word_count`

Точната JSON Schema, която `tools/list` трябва да върне за него:

```json
{
  "name": "word_count",
  "description": "Брои думите в подаден текст, разделени по интервали.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "text": { "type": "string", "description": "Текстът, чиито думи да се преброят." }
    },
    "required": ["text"]
  }
}
```

`tools/call` с `{ "name": "word_count", "arguments": { "text": "..." } }` трябва да върне
брой думи (разделяне по интервали, без празни парчета) като обикновено десетично число,
някъде в текста на отговора — например `{ "content": [{ "type": "text", "text": "Думи: 3" }] }`.
Точният низ около числото не е фиксиран; фиксирано е числото.

Три примера, с които се проверявате (виждате ги и в тестовете, и в автоматичния оценител):

| `text` | очакван брой |
|---|---|
| `"the quick brown fox jumps over the lazy dog"` | 9 |
| `"one"` | 1 |
| `"   spaced   out   words   "` | 3 |

## Съдържание

| Папка | Какво има вътре |
|---|---|
| `demo/` | Работещ MCP сървър с различен инструмент (`ping`), плюс скрипт, който го изпитва стъпка по стъпка. Показва механиката, без да ви дава решението на упражнението. |
| `exercise/` | Стартовият код: `src/server.ts` с два TODO-та, и failing test suite в `tests/`. |
| `solution/` | Бележка; решението е на отделен клон. |
| `.autograder/mcp-server.json` | Командата, с която автоматичният оценител стартира вашия сървър. Не я местете и не я триете. |

## Стъпки

```bash
npm ci                 # само първия път, от тази папка
npm run demo            # вижте протокола в действие с готов сървър (ping)
npm test                 # ще се провали — довършете двата TODO-та в exercise/src/server.ts
npm run typecheck
```

Готови сте, когато `npm test` минава изцяло.

## Ако нещо не тръгне

| Съобщение | Какво значи |
|---|---|
| Тестовете увисват / timeout | Вероятно пишете нещо с `console.log` в `server.ts` и трошите JSON рамкирането на stdout. |
| `tools/list` връща грешка | TODO 1 не е довършен — вижте коментарите в `exercise/src/server.ts`. |
| `tool_invocation_matches_spec` пропада | Проверете как броите думите — интервалите в началото/края и повтарящите се интервали не бива да се броят за думи. |
| Сървърът "умира" след непознат инструмент | Хвърлена грешка е излязла извън `dispatch()`, без да мине през `try/catch`. Проверете дали не сте премахнали обвивката. |
