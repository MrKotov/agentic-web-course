# exercise/ — 06-ship

Задачата: упакуйте приложението си, настройте CI, и го поставете някъде на публичния
интернет.

## Как да работите

1. Напишете `Dockerfile` или използвайте друго решение за контейнеризация.
2. Настройте GitHub Actions (или еквивалент), за да строиш образ и го хвърли някъде,
   всеки път кога натиснете.
3. Подразпоредете (на Heroku, Railway, fly.io, AWS, или каквото предлага вашата
   лаборатория).
4. Проверете, че живия сървър връща 200.
5. Напишете доклад, кой обяснява пропуските между локално и поток:
   - Какво се е променило конфигурацията.
   - Какъв ресурс се е използвал.
   - Какви интеграции липсват (логване,監察, възстановяване).

Готови сте, когато:

- `npm run production:test` минава (в папката или на живия URL).
- CI е зелена.
- Производствен доклад присъства.

За защита е могат да обясните разликите, които сте видели.
